# Maintain a project verification skill

A project's `verify-<app>` and `maintain-verify-<app>` skills were generated by `create-project-verification-skill`, which keeps improving. This pass brings them in line with what that generator would produce today, then runs the project's own full audit. The result is at most one PR.

## 1. Locate the target

Find `.agents/skills/verify-*/` and `.agents/skills/maintain-verify-*/` in the repository. Several apps → ask which one. None → stop and point at `/create-project-verification-skill`.

## 2. Read the current generator

Read `create-project-verification-skill`: its `SKILL.md` and everything under its `references/`. It is installed next to this skill (`../create-project-verification-skill/` from this skill's folder). That is the spec for what the project's skills should look like.

## 3. Conform

Compare the project against the spec and fix every difference, keeping what is project knowledge:

- **Keep:** the feature files' content, launch and doctor commands, the chosen isolation option, sign-in, gotchas, helper scripts that still work. These were learned about this project; don't regenerate them.
- **Bring up to date:** the file layout, frontmatter and descriptions, the sections `verify-<app>` must have and their rules, the feature file shape, `maintain-verify-<app>` and its `agents/openai.yaml` (recopy from the references, reapplying any project-specific adjustment), both Claude Code stubs, the `.gitignore`, the helpers the generator requires (such as `bin/pw.sh`), where run output goes, and the line in `AGENTS.md`.

When the spec now asks for a decision the project never made (for example, a new section that depends on how the app runs), make it the way steps 1 and 2 of the generator describe, asking the user only what the repo can't answer.

## 4. Audit

Run the Pass from `maintain-verify-<app>` on the conformed skill, then its Ship section. The conformance edits and the Pass's corrections go in the same branch and the same PR. If both found nothing, the outcome is `clean` and nothing is opened.

## 5. Report

Say what changed to match the generator, then report per the Ship section: the outcome, one line per feature, and the product gaps found.
