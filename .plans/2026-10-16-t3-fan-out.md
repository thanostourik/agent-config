# T3 fan-out skill

## Goal

One shared skill, `t3-fan-out`, that a T3 Code thread (the coordinator) runs
to start one thread per task, wait for them, hand out verification, and
report back.

## Design

- `skills/shared/t3-fan-out/SKILL.md`, no `harness` field: every provider can
  call the `t3-code` MCP tools, so it goes to all five tools. Enabled entry in
  `config.example.json`.
- Start each task with `t3_thread_launch`, not `delegate_task`:
  `workspaceStrategy` `{type: "worktree", baseRef: "main", branch,
  startFromOrigin: true}` cuts the worktree from up-to-date origin main and
  names the branch. `delegate_task` with `isolation: "worktree"` only forks
  the coordinator's local commit and cannot name the branch.
- Branch `<prefix>/ISSUE-123-short-name` (`feature/`, `fix/`, `chore/`), issue
  id omitted when there is none.
- The first prompt stands alone: task, issue key, everything the user said
  about it, and "implement, commit, push, open the PR, do not verify yet".
- Model per thread as the user names it; unnamed threads run on
  `claudeAgent` / `claude-opus-5-5` with `effort: high`. Every combination is
  checked against `orchestrator_capabilities` first; a missing one is a
  question to the user, never a fallback.
- Wait with `t3_thread_wait`, one thread after another, calling it again on
  timeout. No progress messages.
- Verification is one thread at a time through `t3_thread_send` "verify now"
  and `t3_thread_wait`. If the target project's instructions allow parallel
  verification, the first prompt tells each thread to verify right after its
  PR instead.
- Final report: one line per thread with verdict, PR link, and what is
  unverified.

## Verification

`python -m unittest discover -s tests -v` and `./sync --home <temp dir>` to see
the skill installed for every tool. A real fan-out run is not verified here.
